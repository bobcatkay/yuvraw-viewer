## 并排对比

对比面板的“对比模式”对用户只提供三种选择：**单图切换 / 差值图 / 平铺**。
`EViewTarget::Main` 与 `EViewTarget::Compare` 仍作为“单图切换当前指向哪个槽位”的内部状态，
不能为了合并两个单选项而丢掉它们，否则文件浏览器替换当前槽位、属性回填和直方图目标都会失去依据。

主图与对比图都有效且处于单图切换时，viewport 内左键点击并抬起会在两者之间切换；
拖动平移后抬起不触发切换。
`FImageViewer` 只在本帧使用完旧文档后发出切换请求；`FMainDockSpace::SwitchSingleImageView()`
统一更新 `EViewTarget`、查看器文档、属性面板编辑目标与直方图，不能在查看器里直接改文档指针。
单图切换在 viewport 左上角以主题高亮底色显示当前槽位身份（“主图”/“对比图”），后接半透明底色的
当前文件名（只显示 basename，保留扩展名）；平铺模式仍显示
槽位身份（“主图”/“对比图”）。首次三次进入这组状态时，
viewport 顶部显示“点击左键切换对比图”，每次最多显示 3 秒；次数通过
`FUserSettings::ConsumeSingleImageCompareHintDisplay()` 写入 `settings.ini`，只在模式进入边沿消费，
提示期限使用 `steady_clock` 记录，禁止在逐帧 Render 中重复递增、写盘或重新开始倒计时。

最近一次由用户主动选择的“单图切换 / 平铺”通过 `FUserSettings::Get/SetCompareMode()`
写入 `settings.ini`，加载新对比图时恢复；单图切换下先显示新加载的对比图。
“差值图”是临时计算结果，不属于持久化枚举，也绝不能覆盖已记忆的模式。程序内部因清空图片、
替换文档而调用 `SetViewTarget()` 时同样不改偏好，只有面板单选项的用户操作可以更新。

`FImageViewer` 持有 `Document`（主）与 `SecondaryDocument`（副，非拥有）。副文档非空即进入并排模式：
画布左右均分，`IssueDrawCallback()` 调两次，各自带自己的 scissor 区域。

主图与对比图各自持有一份 `FImageViewSettings`（显示模式 / 手动比例 / 平移 / 朝向）。
单图切换模式始终联动两份状态里的显示模式、手动缩放与平移：当前显示文档是唯一真值，隐藏文档
每帧以及每次交互后跟随，因此切换、恢复缓存或替换文件时画面位置都不跳变；旋转与镜像仍各自独立。
工具栏操作作用于属性面板当前编辑的图片；点击任一 pane 或在其上 Ctrl+滚轮时会先把它设为当前图片。
顶部缩放框后面的链条按钮只在平铺模式显示，默认选中：选中时两侧联动显示模式、手动缩放和
平移，旋转与镜像仍各自独立；取消选中后所有视图变换互不影响。重新开启时以当前选中 pane 的
缩放/平移状态对齐另一侧。切换文件前仍由 `FMainDockSpace` 把两份状态分别归档到按路径配置缓存。
链条、水平并联和垂直并联三个按钮的持久选中底色同样读 `FUiTheme`；未选中态以及其它工具栏控件
继续使用全局主题色。

要点：

- 自适应/填充的 scale 要按 **半个画布宽**算（`paneWidth`），否则图会被分隔线切掉
- Ctrl+滚轮的缩放锚点相对**鼠标所在的那一半**计算；同步开启时另一侧使用相同的 pane 内
  相对位置作锚点并缩放到同一比例，同步关闭时只更新鼠标所在图片
- 像素探针在并排模式下同时取两侧**同一坐标**的值，用三列表格给出 主图/对比图/差值

## 视图朝向（镜像 / 旋转）

图片右上角悬浮区的四个镜像/旋转图标按钮改的是目标图片 `FImageViewSettings` 的三个字段
（`RotationQuarters` 0-3 顺时针步数 + `bFlipH` / `bFlipV`），**不动 `FImageData`、不重建纹理**；
并排时两侧各用各的状态。查看器工具栏的“重置”只重置当前图片的视图配置。

约定的变换是 **M = 旋转 · 镜像**，即先镜像后旋转。而四个按钮都作用在**屏幕空间**上
（"把现在看到的这幅图再翻一下"），于是：

| 按钮 | 状态更新 |
|---|---|
| 顺/逆时针 | `RotationQuarters ± 1`，镜像标志不动（旋转互相交换） |
| 水平/垂直镜像 | `RotationQuarters = -RotationQuarters`，再翻对应标志位 |

镜像那条的旋转取反不是笔误：反射会把旋转共轭成它的逆，`Fx·R(θ) = R(-θ)·Fx`。
漏掉它的话，"旋转 90° 后再点水平镜像"会变成沿垂直方向翻转。两个标志同时为真时
等价于旋转 180°，`NormalizeOrientation()` 把它折进旋转里，保证 8 种朝向各只有一种表示。

三处必须一起改，漏一处就会错位：

1. **布局**（`fitWidth/fitHeight`、`PaneRenderSize`）—— 90/270 度时宽高互换，
   自适应/填充/缩放锚点全部按旋转**之后**的尺寸算，否则竖过来的图会被画布切掉
2. **绘制**（`RenderCallbackData::RotationQuarters/FlipX/FlipY`）—— `RenderPos/RenderSize`
   传的是旋转后的屏幕包围盒，四边形本身按未旋转尺寸建，所以回调里要把两边换回来。
   投影是 `glm::ortho(0, w, h, 0)`，**Y 轴朝下，绕 +Z 的正角度在屏幕上就是顺时针**，不要取反
3. **像素探针** —— 屏幕坐标先归一化到显示矩形，再逆着"先镜像后旋转"的顺序还原。
   正向映射（θ 为顺时针度数，a=x/W, b=y/H）是
   `90°: u=1-b, v=a` / `180°: u=1-a, v=1-b` / `270°: u=b, v=1-a`，代码里写的是它们的逆

验证方式：旋转 + 镜像之后用探针点一个能认出来的特征（瓶盖之类），
报出来的坐标应当与在**未旋转**视图里量到的同一个特征一致 —— 这是唯一能同时
检出布局、绘制、探针三处错位的办法，光看画面正不正只能查出前两处。

缩放输入框与属性面板的"曝光"是同一种控件（`DragFloat`，可拖动也可双击输入），
额外加了 `ImGuiSliderFlags_Logarithmic`：量程 `kMinZoom`~`kMaxZoom`（当前 2%~5000%）
横跨多个数量级，线性拖动难以兼顾低倍率精调和高倍率快速调节。

对数模式下 ImGui 先把 `v_speed` 除以量程再作用在 [0,1] 参数空间上，所以速度是由
`kZoomDragFullRangePixels`（拖满全程要多少像素）**反推**出来的，不是写死的魔数 ——
改量程时手感自动跟着走。**`kMaxZoom` 同时也是 Ctrl+滚轮和 `SetZoom()` 的上限**，
改一个常数三条路径一起变，不要在拖动框上另写一份边界。

## 关闭当前图片

单图、单图切换、差值图和两种平铺方向的每个可见图片右上角都有独立的 `x` 关闭按钮，
位于镜像/旋转组右侧，背景单独绘制；组间距使用 `ImGuiStyle::ItemSpacing.x`，与“自适应 / 填充”一致。
`MakePaneOverlayLayout()` 与 `GetPaneOverlayButtonPosition()` 统一布局和命中几何，
关闭区域同样排除画布切换、平移和探针交互，窄画布的文件名避让也使用完整控件宽度。

查看器与对比面板的关闭入口都只记录 `FMainDockSpace::PendingDocumentClose`。
下一帧在后台差值/导出结束、上一帧 OpenGL 回调已执行后，先处理关闭，再提交图片加载结果；
不能在悬浮按钮的点击回调中直接释放图片。关闭前归档源图配置，并取消被关闭槽位的待加载请求。

关闭主图时，若对比图仍有效，必须将它转为主图，不能只把查看目标切到 `Compare`。
`FImageDocument::TakeContentFrom()` 转移路径、加载参数、色彩设置、像素、纹理和错误状态，
保留固定槽位地址与各自回调；查看器同步迁移缩放、平移和朝向，不重新解码或上传。
转移后清除对比图标记，文件浏览器在当前目录中把新主图设为普通选中并更新 Shift 锚点，
属性与查看目标统一回到 `Main`，从而允许继续添加其它对比图。关闭主图时取消全部旧槽位加载请求。
没有剩余图片则清除普通选中并回填空主图；关闭对比图只清除对比图标记。
任一源图关闭都会使差值图和统计失效，属性与直方图随后统一回填。
只关闭差值图时保留两份源图并回到主图。关闭不会改写记忆的对比模式。
只有两份源图都存在时才允许平铺，并显示属性面板的编辑目标下拉框。

## 像素探针的右键复制

悬停时的浮窗底部写着"右键复制所有信息"，右键把当前显示的内容原样拷进剪贴板
（`BuildProbeText()`，制表符分列 + **CRLF** 换行 —— Windows 剪贴板的惯例，
只认 CRLF 的程序会把 `\n` 粘成一整行），随后 `FToast::Show()` 弹一条回执。

命中判定不用再写一遍：`RenderPixelProbe()` 只在 `ProbeX/ProbeY` 有效时才被调到，
而它们有效就等于鼠标正悬在画布上；忙碌时画布被 `BeginDisabled` 罩住，探针根本不出现。

`FToast` 与 `FUiIcons::DrawBusyOverlay()` 同一套路（前景绘制列表，不开窗口），
`FToast::Render()` 在 `FMainDockSpace::Render()` 里排在忙碌遮罩**之后**，
否则长任务结束那一瞬间的回执会被遮罩压住。

## 显示设置按文档存放

色彩标准 / 数值范围 / 通道隔离（`FDisplaySettings`）挂在 **`FImageDocument`** 上，不在查看器上。
`IssueDrawCallback()` 读的是被画的那个文档自己的设置，所以并排时两侧可以各用各的。

属性面板顶部的"编辑对象"下拉框决定它在编辑哪一个文档（两份源图都存在时才出现）：

- `FMainDockSpace::GetTargetDocument()` 是唯一的判定入口，回填（`SyncPanelFromDocument`）
  与提交（`SubmitPanelToDocument`）都走它
- 两个文档的 `OnChanged` 都接到 `OnDocumentChanged(doc)`：只有正被编辑的那个才回填面板，
  否则只重算直方图 —— 否则加载对比图会把主图的面板内容冲掉
- 打开新主图时若面板停在对比图上，**不能**把面板上的参数套给主图，只把编辑对象切回主图

显示设置改动不触发重新加载（不影响解码），但**要重算直方图**（色彩标准变了统计结果就变了）。

## 系统拖放的派发

GLFW 的 drop callback 只给文件列表，不给坐标。落在哪个面板上靠松手时的光标位置判断：

1. `FApplication::HandleFileDrop` 里 `FWindow::GetCursorPos()` 取位置 ——
   GLFW 在派发回调前刚把光标位置更新成松手处，读到的就是对的
2. 存进 `FMainDockSpace::PendingDropPaths`，**等本帧所有面板渲染完**再由 `ProcessPendingDrop()` 派发；
   那时各面板才更新过自己的屏幕矩形（`ContainsScreenPoint`）
3. GLFW 给的是窗口客户区坐标，面板矩形在开启多视口后是桌面坐标，**差一个 `GetMainViewport()->Pos`**

别改成用 `ImGui::IsWindowHovered()`：拖放过程中主窗口未必有焦点，ImGui 后端此时不更新 `io.MousePos`。

## 文件浏览器键盘切图

ImGui 的导航焦点与应用自己的选中状态是两回事：普通 `Selectable` 接收上下键时只移动焦点，
不会返回激活事件。文件行通过 `FUiIcons::IconSelectable` 按需启用 `SelectOnNav`，让焦点落到
新文件时仍统一走 `FFileExplorer::HandleFileClick()`，从而同步 `SelectedFiles` 并触发
`OnFileSelected` 打开图片。目录行不能启用这个行为，否则从第一张图片按上键越过列表边界时
会直接进入目录。

`OnFileSelected` 不再固定打开主图，而是按对比面板当前的 `EViewTarget` 路由：单图切换时替换
当前正在显示的主图或对比图，差值图模式替换主图并回退为主图，平铺模式则根据查看器当前选中的 pane
替换主图或对比图并保持平铺。平铺的选中 pane 与属性面板编辑目标保持同步，因此统一通过
`FMainDockSpace::GetTargetDocument()` 判断。菜单打开、最近文件与系统拖放仍走 `OpenPath()`，
保持“替换主图并显示主图”的语义，不能和文件浏览器普通选图的上下文路由混用。

普通选中（青色）同时承担主图身份标记，`CompareFileKey`（琥珀色）独立标记对比图。因此
`FileSelectedCallback` 必须返回本次激活是否替换主图：返回 true 才更新 `SelectedFiles` 与
Shift 锚点；替换对比图时返回 false，保留主图选中。鼠标点击、键盘导航和右键“打开”都走
同一返回值规则，不能在调用回调之前无条件改写 `SelectedFiles`。

`MainFileKey` 单独记录实际打开的主图；与 `CompareFileKey` 一样，只在加载成功、关闭或槽位转移时更新，
不随多选及尚未完成的加载请求改变。文件右键菜单对当前主图和已有对比图隐藏“添加为对比图”，
其它文件仍显示该入口；路径键统一相对/绝对路径、分隔符与大小写。
